W4 · 计费与个人中心

这是合规密度最高的一页。四条硬约束贯穿始终： ① iOS 版必须单独一套（零站外支付引导）； ② 免费给的东西必须显式写「免费」（否则钩子反向失效）； ③ 取消续费不得比开通更难； ④ 支付必须画到「结果」为止（🔴 [D25]：只有购买页没有支付结果 = 用户付了钱却没到账时无路可走）。

🔴 数值纪律：本页所有价格与中继时长数值均为示意占位，实际由定价版本管理（D14）后端下发；且 成本测算表 §10.2 的 TURN 报价到手前，对外材料不得出现具体数值。
🔴 术语纪律：付费买到的是「中继时长」；只有免费档配额才叫「免费中继时长」（用户可见文案一律遵守，见 README §6.1）。

3 · 支付链路（订单确认 → 支付结果 → 扣款失败）与 Web 购买入口

本节补的是同一个洞：此前全稿只有「购买页」（下单前）， 没有「支付本身」。支付是全流程唯一「钱已经出去、权益还没到」的状态 —— 缺了它，用户唯一的求助路径是找客服。第四帧补的是 商业化 §10 早已定下却从未出图的一处：「Web / 桌面端应作为主购买入口」。

🔴 口径纪律（[D25]）：本节只画我方界面。微信 / 支付宝的收银台页、Apple 的支付弹层不是我方界面，不出稿； 需要出稿的是跳转前（订单确认）· 跳转中（确认中）· 跳转后（结果）三段。
⚠️ 本节仍不得出现：倒计时优惠 · 「已省 xx 元」· 支付结果页的任何推荐位 · 被控端同步展示（商业化 §13.4 红线②⑤）。

W4-10 · 🔴 支付结果五态（缺任意一态 =「钱付了、权益没到」无处可查）

按顺序看：A 已开通 · B 未完成 · C 确认中（回调未达） · D 订单已关闭（超时） · E 查询用尽 → 人工对账（🔴 `[D27]` 新增）。 🔴 C 是本组的核心 —— 它是「钱已经出去了、权益还没到」这段真空期的唯一出口； 而 E 是 C 的尾巴 —— 没有 E，C 就是无限等待。
五态各自有锚点，可单独引用： A · B · C · D · E。
