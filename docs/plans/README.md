# 开发计划 · 阶段总览

> 状态：2026-09-19 · 只排已拍板的范围，**不新增产品决策**。
> 需求以 `需求规划-v2-P0P3重构` §1 为准，发版闸门以该文档的 P0 发版阻塞项清单为准。
> 价格、免费中继时长、设备数只引用 `成本测算表` §0，界面上的数字必须后端下发。

## 0. 能不能分成 MVP、S1、S2……Sn

能。Sn 不是另一套优先级，只是把已经写过的 P0–P3 排成开工顺序。

| 阶段 | 对应已有优先级 | 这一阶段结束时 |
|---|---|---|
| **MVP** | P0 里**挡住发版**的部分 | 第一个可发布版本：电脑控电脑能用，合规和计量关得上 |
| **S1** | P0 内第二优先级 | 手机被控钩子上线。不挡住 MVP |
| **S2** | P1 | 体验、插件、iOS 控制端、完整个人中心 |
| **S3** | P2 | 眼镜只做手机的显示和耳机，不直连远程桌面 |
| **S4** | P3 | **不排期**。硬件条件不到，不做工程承诺 |

没有 S5。再往后的事在需求文档 §7「明确不做」里，不占阶段号。

P0 这一层故意拆成 MVP 和 S1，因为需求已经写明：安卓被控端留在 P0，但是第二优先级，**不阻塞发版**。把它和「第一个可发布版本」捆在一起，会让手机机型风险挡住电脑主路径。

## 2. 排期时不能改的几条

- 连接模式指示器、降级四态、转直连引导，排在购买页前面。它们是已拍板决策的执行体，不是体验优化。
- 付费墙只挂在中继上。直连不消耗免费中继时长。
- 安卓被控、电脑控手机，不得挤占 MVP 的人力。
- 月付是连续包月。扣费前 5 日提醒留在 MVP，不能挪到 S2。
- TURN 报价未到手：阻塞对外写具体额度，**不阻塞开发**。数值后端下发，报价录入后重算。
- 通道数 / 会话数仍未拍板（评审意见 §10.5）。不挡 MVP 开发，挡对外主张。本计划不替它做决定。
