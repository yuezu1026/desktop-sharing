> 状态：2026-09-19 · 只选实现手段，**不新增产品决策**。
> 阶段范围以 `README.md` 为准。三面划分以 `商业化与计费设计` §6 为准。

## 0. 五门技术各自放哪

已经拍板的系统是三面，不是一个大单体：

| 面 | 职责 | 用什么 | 不用什么 |
|---|---|---|---|
| **控制面** | 账号、设备、权益、订单、额度账本、签发一次性 ticket | **TypeScript** | 不用 Java / Spring Boot。不碰画面字节 |
| **数据面** | 信令、打洞、中继转发、服务端限码率 | **Rust** | 不把 PostgreSQL 放进转发热路径 |
| **计量面** | 中继自己数字节，写入账本 | Rust 上报，TypeScript 入账 | 客户端不是计量源 |
| **电脑被控端** | 常驻、采集、编码、托盘、一键断开 | **Rust** | 不用 React Native，不用 Tauri，不用任何内嵌浏览器 |
| **电脑控制端** | 解码、等比渲染、键鼠 | **Rust** | 不用 Tauri，不用 React。画面不进网页视图 |
| **手机** | 账号与手持界面；画面仍走 Rust | **React Native** 做界面，Rust 做会话 | 不用 JavaScript 做编码或注入。不另做一套 React 网页壳 |
| **Web 控制端** | 一次性授权码，只控不控被 | **TypeScript** + Rust 编出的 WASM | 不能当被控端。页面壳可以是 React，解码不是 |
| **官网 / 运营台** | 购买页、内部 3 查 3 动作 | **TypeScript + React** | 运营台不复用 C 端登录。不单独配一套 Java 后端 |
| **数据** | 上面这些的权威记录 | **PostgreSQL** | 不存画面、不存剪贴板、不存中继明文 |
| **部署** | 本地与上线的同一套进程边界 | **Docker** | 中继容器不挂媒体卷 |

中继是我们自己的 Rust 进程：两端各做一段传输加密，中继在中间转发，所以它技术上能看见内容。这和已经写明的口径一致——中继可解密，对外不得把所有连接都叫端到端加密。限码率不靠把画面解码出来，靠中继自己数转发的字节，超过 ticket 里的上限就不再往前送。画面字节只留在内存里，不写日志、不写磁盘。不换成「只搬密文」的现成 TURN：那种中继看不到内容，和这条口径对不上，码率上限也落不到我们的进程里。直连是另一条路：密钥只在两端，服务器只收到会话起止、打洞结果和实际码率，不拿这些数据扣免费中继时长。

## 1. 仓库怎么切

还没有客户端代码。按下表长出来，不要先做一个「全端共享 UI」。

| 目录 | 语言 | 阶段 |
|---|---|---|
| `crates/session-core` | Rust | MVP。加密、帧、输入事件、ticket 校验。桌面直接链接；手机经原生模块调用；Web 只用其中可编译到 WASM 的部分 |
| `services/control-plane` | TypeScript | MVP。注册、登录、设备、订单、支付回调、账本、ticket。没有第二个后端 |
| `services/signal` | Rust | MVP。在线状态、候选地址交换、打洞协调 |
| `services/relay` | Rust | MVP。TLS 443 转发、数字节、掐码率、按 ticket 停转 |
| `apps/desktop-host` | Rust | MVP。只做 Windows / macOS 被控 |
| `apps/desktop-controller` | Rust | MVP。Windows / macOS 控制 |
| `apps/mobile` | React Native | MVP 只做 Android 控制端。S1 才加安卓被控。S2 才出 iOS 控制端 |
| `apps/web-controller` | TypeScript | MVP。页面壳可用 React，解码用 WebCodecs |
| `apps/web-site` | TypeScript + React | MVP。官网购买，微信 / 支付宝。只调控制面 |
| `apps/ops` | TypeScript + React | MVP 最小版。独立登录。定价后台和成本报表留到 S2 |
| `deploy` | Docker | 与上面的进程一起出现 |

`session-core` 是唯一的协议实现。控制面用 TypeScript 签发和校验 ticket 的字段，但字节级帧格式不在 TypeScript 里再写一遍。

注册、登录、支付、运营台都在这一条控制面里，不另起 Spring Boot。这些写的是同一本账：账号、订单四态、额度扣减、ticket。再加一个 Java 进程，PostgreSQL 就有两个写入方，支付回调和计量心跳会对不上。React 只用于官网和运营台（Web 控制端的页面壳也可以用）。手机仍是 React Native，桌面仍是 Rust。运营台和官网是两个前端，不共用登录。

## 2. 一条中继会话怎么走

时序以 `商业化与计费设计` §6.1 为准，这里只标进程：

1. 控制端向 **control-plane** 要会话。控制面查账号、设备数、权益、额度余量。通道数和每通道会话数的上限字段留着，**具体数字尚未拍板**（评审意见 §10.5），客户端不得写死。
2. 控制面签发一次性 ticket：账号、两端设备、码率上限、额度上限、短 TTL。
3. 两端先经 **signal** 交换候选地址，后台打洞。打洞失败不弹窗，当前画面不停。
4. 打洞未通时，两端拿 ticket 连 **relay**（TCP / TLS 443，封 UDP 的网络也必须能通）。relay 向控制面验票，通过才转发。
5. relay 每 30 秒把本会话的字节数和时长报给控制面。控制面在一个数据库事务里按先到期先扣记账，并回「续票 / 降档 / 停转」。没有有效 ticket，relay 停止转发。不能只在进门时查一次额度。
6. 直连打通后，relay 这条停掉，改为两端上报起止。这笔不上账本。

降级四态的判定在控制面，执行分两处：降码率由 relay 掐；停转发由 relay 执行；画面上的横幅和「仅查看」由客户端按控制面的指令画。客户端自己降画质不算数。

两种仅查看不要做成同一个开关。资源式：relay 停掉视频帧，控制端留下最后一帧。权限式：帧还在走，只是输入事件被被控端丢掉。

## 3. 各端怎么接 Rust

**电脑被控端**是常驻进程。需求要求静置时 CPU 均值低于 1%、GPU 占用为 0、常驻进程不超过 3 个（服务态、用户态、提权代理），编码器懒加载。React Native 和任何内嵌浏览器都过不了这条，所以被控端界面也用 Rust 画，不用手机那套组件。

**不用 Tauri。** Tauri 的界面跑在系统网页组件里（Windows 上是 WebView2）。这个组件自己就会再拉出浏览器进程、渲染进程和 GPU 进程，静置时 GPU 也占着。被控端主界面要常驻显示识别码，不是「偶尔弹一个设置窗」，所以省不掉这组进程。进程数会超过 3 个，GPU 也做不到 0。控制端同样不用：远程画面要走 GPU 等比合成，连接方式角标要留在这一层里；放进网页视图会多一次拷贝，也和「全屏时角标不能跟着工具条一起消失」拧着。账号页、购买页已经是 TypeScript 网页，不需要为了复用 HTML 再在桌面端嵌一个浏览器。

进程分工：

- 用户态：托盘、识别码、临时密码、首次确认。空闲时不做采集。
- 服务态：开机拉起。没有会话时不占编码器。
- 提权代理：只在需要注入或跨会话采集时存在。一键断开直接停掉转发和采集，不再弹第二次确认。

**电脑控制端**同样用 Rust 解码和渲染：等比、两侧留边、不改被控端分辨率。全屏是用户动作；工具条可以藏，连接方式角标留在合成层里，不跟工具条一起被摘掉。

**手机**用 React Native 做导航、账号、列表和手持布局。会话画面、解码、触控采样放在原生模块里，由 `session-core` 处理。Android 控制端是 MVP：手持、放大镜、双模指针，可点区域至少 44px。不要在这一层做安卓被控。

S1 的安卓被控仍是同一个 React Native 工程里的另一组界面，但屏幕录制、无障碍、前台服务、编码必须是原生代码。JavaScript 轮询屏幕既做不到息屏，也守不住「未授权只降级、不阻断」。音频三件套同批做：采集和静音在原生层，界面只显示「正在采音」和静音开关。播放走系统播放，不在 MVP 里做驱动。

**Web 控制端**不登录。已登录的客户端生成一次性短时授权码，Web 凭码建会话，账记在生成方账号上。解码用浏览器自己的 WebCodecs，密钥和拆帧用 WASM，避免再维护一套协议。不在浏览器里做被控。

## 4. PostgreSQL 存什么

一个库，控制面是唯一写入方。relay 不直接连库，避免转发进程被数据库拖住，也避免帧流经数据库网络。

| 表组 | 存什么 | 不存什么 |
|---|---|---|
| 账号 | 手机号、可选邮箱、密码、恢复码状态 | 生物特征 |
| 登录会话 | 这台设备上的登录 token | 不得和「被控设备」合成一张表 |
| 被控设备 | 设备三态、授权、识别码 | 临时密码只存哈希，不明文 |
| 可信配对 | 两侧都标记过的配对 | 不另造一套账号 |
| 权益与价格版本 | 下单价、生效期。订单确认时记下当时的版本号 | 不在客户端写 ¥158 / ¥24 |
| 账本 | 以 GB 为记账单位，先到期先扣。分钟只是查询时折算 | 不把「剩余分钟」当权威列 |
| 订单 | 待支付、已支付、确认中、已关闭。幂等键是订单号 | 不信客户端回传的支付结果 |
| 连接元数据 | 起止、是否直连、打洞分桶、持续时长、字节数 | 不存画面、不存键鼠、不存剪贴板 |
| 内部账号 | 邮箱、密码、强制二次验证、审计 | 不复用用户手机号；不开自助注册 |
| 成本参数 | 报价、生效期、来源。单位成本和免费额度由计算得出 | 后台不得手填计算结果。管理界面可以晚于表结构，表不能晚 |

设备数免费版和个人版都是 150，是权益配置，不是付费开关。

留存：连接元数据保留 6 个月，到期由控制面的定时任务删除，不靠人。注销后 30 天内只标记；期满再删身份、把计量流水去标识。保留期不得短于这 30 天。

通道数 / 会话数未拍板。表里可以有上限列，值由配置下发；在拍板前不要把某个整数写进迁移脚本当成产品规则。

## 5. Docker 怎么摆

本地用一份 Compose，把进程边界固定下来。生产不要为了省事把中继和数据库放进同一个容器。

| 容器 | 有状态吗 | 卷 |
|---|---|---|
| `postgres` | 有 | 只挂数据库文件 |
| `control-plane` | 无。状态在库里 | 无 |
| `signal` | 连接期内存态 | 无 |
| `relay` | 帧在内存 | **禁止**挂载任何卷。日志只打连接元数据 |
| `web-controller` / `web-site` / `ops` | 无 | 静态文件即可 |

relay 单独扩容。多开几份时，控制面按 ticket 把会话粘在其中一份上，不在两份 relay 之间拆同一路画面。信令要能在封 UDP 时仍给出「走 443」这条候选，而不是只返回 UDP 地址。

密钥和支付密钥走环境变量或编排系统的密钥存储，不进镜像，不进仓库。

## 6. 跟阶段怎么对齐

**MVP 就上线的**

- 上表里除「安卓被控、音频、iOS」以外的全部进程。
- 桌面被控 + 桌面控制 + Android 控制端 + Web 控制端。
- 微信 / 支付宝下单、回调、确认中状态、扣费前 5 日提醒。收银台是渠道的页面，不自己画。
- 运营台：内部登录、用户 / 计量 / 订单查询，调时长、封禁加白、退款跳到渠道后台。计量查询读账本，不读另一份汇总。

**S1 才接的代码**

- `apps/mobile` 的被控模式：录屏、无障碍、前台服务、机型分档。
- 桌面控制端对手机画面的等比和触控映射。协议不变。
- 音频在 `session-core` 里单开一条可以独立停的通道。静音必须能在 1 秒内停采集。纯音频不参与「剩余分钟」折算。
- 机型通过率低于 60%，这段从发布里拿掉，不留半套开关。

**S2 才接的代码**

- 同一 React Native 工程出 iOS 控制端。购买只留应用内购买，工程上用编译开关去掉微信、支付宝和比价入口，而不是靠隐藏按钮。
- 外接大屏、虚拟麦摄像头、高帧率插件、定价与成本的管理界面、完整个人中心。
- 虚拟设备需要签名驱动，不塞进 `session-core` 的 MVP 路径。

**S3 / S4**

- S3 不新作协议。眼镜接的是手机，手机仍是控制端。
- S4 不预留接口，不在 `session-core` 里加「眼镜端」角色。

## 7. 这套选型故意不做什么

- 不用 TypeScript 写中继或桌面常驻被控端。计量和空闲 CPU 都守不住。
- 不用 Java / Spring Boot 再做一套注册、登录、后台或支付。控制面只有 TypeScript 一个写入方。
- 不用 React 做桌面或手机。React 只做官网、运营台，以及 Web 控制端的页面壳。
- 不用 React Native 包一层 Windows 被控端。
- 不用 Tauri，也不在桌面端嵌 WebView。被控端守不住空闲占用；控制端的画面路径会绕远。
- 不把画面、剪贴板、中继明文放进 PostgreSQL、日志或对象存储。剪贴板只在会话内存里，两端传递。
- 不引入第二套数据库。在线状态和未过期 ticket 放在 PostgreSQL 里即可；等连接规模真的顶满，再单独立项缓存，不在 MVP 加组件。
- 不把「运维实时看用户画面」做成功能。帧不落盘，会话结束即从内存消失。将来若要调阅，先有审批和审计，再谈实现。
- 国密套件是体验阶段的可选项，不放进 MVP 的握手。
